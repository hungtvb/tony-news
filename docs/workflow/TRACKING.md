# Workflow Tracking

This file records the project-wide process invariant:

- Every non-trivial work item starts with a written plan.
- Every non-trivial work item has a GitHub issue before implementation begins.
- Large items use a parent tracking issue plus child tasks.
- Progress, blockers, decisions, verification, and evidence are updated in the issue.
- Scope expansion requires a new or updated task before implementation.

The canonical detailed rule is [`plan-and-task-first.md`](./plan-and-task-first.md).
